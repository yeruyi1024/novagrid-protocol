# NovaGrid v1 兼容性策略

## 版本

- 协议 Tag 使用语义化版本；冻结前为 `0.x`，冻结后从 `v1.0.0` 开始；
- OpenAPI `info.version`、Protobuf package 和 JSON Schema `schema_version` 共同标识协议代际；
- 消费者必须固定发布 Tag，不得长期依赖 `main`。

## 兼容变更

允许在同一 major 中：

- 新增可选字段；
- 新增消费者能够按未知值降级处理的枚举值；
- 放宽不会破坏安全和资源边界的输入限制；
- 增加新的事件类型或错误码。

消费者读取 JSON 时必须忽略未知可选字段；Protobuf 依靠未知字段保留实现向前兼容。未知必选语义、未知 `oneof` 消息和未知状态不得猜测，应安全拒绝或降级为不可调度状态。

## 破坏性变更

以下变化必须升级 major，并提供迁移计划和项目负责人批准的 ADR：

- 删除、重命名字段或复用 Protobuf 字段号；
- 改变类型、单位、必选性、敏感性或既有含义；
- 收紧已发布合法输入；
- 改变状态机、幂等、Lease、deadline 或用量语义；
- 改变系统权威边界。

## 检查方式

- `buf breaking --against <已发布基线>` 检查 Protobuf；
- OpenAPI 与 JSON Schema 变更由机器解析、样例和人工兼容审查共同检查；
- 每个发布必须保留合法、非法、边界和未知可选字段样例；
- 初始版本没有历史基线，首次 Tag 建立后才启用相对基线检查。
